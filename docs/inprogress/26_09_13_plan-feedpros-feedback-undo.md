
# Контекст

- Репозиторий `C:\PROJECTS\feedPros` пока не содержит кода расширения: из рабочих файлов отслеживаются только `.gitattributes` и `.gitignore`.
- Источник требований: `docs-01/plan.md`. Реализуется только функция **Feedback + Undo**; Roll-система не входит в этот план.
- `InlineSummary-main` — только референс подключения кнопок, генерации, настроек и сохранения чата. Не копируй его функциональность суммаризации и внутренние ключи `ILS_*`.
- Целевая форма — устанавливаемое клиентское UI-extension SillyTavern с `manifest.json` в корне репозитория.
- Минимальная версия SillyTavern — `1.17.0`: план опирается на современный `Popup`, объектный вызов `generateRaw()` и актуальные extension events.
- Все кнопки показываются на пользовательских, ассистентских и системных сообщениях.
- Контекст запроса — весь актуальный чат: выбранное сообщение удаляется со своего места и его текущий текст добавляется последним как цель изменения. История не обрезается молча; переполнение контекста считается ошибкой.
- Результат заменяет только текст и активный swipe, не создаёт новый swipe и не меняет роль, имя, вложения или прочие данные сообщения.
- Один Undo-буфер действует на все сообщения текущего чата, переживает перезагрузку страницы и очищается при реальном переходе в другой чат.
- Таймаут Feedback — 30 секунд. Внешний запрос через `generateRaw()` нельзя гарантированно отменить извне, поэтому поздний результат обязательно игнорируется по идентификатору операции.
- Генерация выполняется без потокового UI через raw/quiet-путь SillyTavern. Не добавляй собственный streaming consumer.
- Выбранные Connection Profile и API Preset применяются временно и восстанавливаются при успехе, ошибке, таймауте и смене чата.
- Локального запуска SillyTavern в рабочем дереве нет. Чистая логика должна проверяться автоматически; финальный UI/API smoke-тест проводится в установленном SillyTavern.
- Не реализуй серверный плагин, собственный API-прокси, хранение секретов или отдельную базу данных.
- Не выполняй `git commit`, `git revert`, `git reset --hard` и не откатывай пользовательские изменения.
- Все нестандартные комментарии в коде должны объяснять причину решения, а не пересказывать действие.

Целевая структура:

```text
feedPros/
├─ manifest.json                 — манифест устанавливаемого расширения.
├─ index.js                      — инициализация, события, кнопки и координация действий.
├─ common.js                     — константы, runtime-lock и общие безопасные помощники.
├─ prompt.js                     — чистая сборка запроса из истории и фидбэка.
├─ generation.js                 — профиль/preset, raw generation, таймаут и защита от позднего ответа.
├─ undo.js                       — снимок, валидация, применение текста и общий Undo-буфер.
├─ settings.js                   — загрузка, сохранение и обновление настроек.
├─ settings.html                 — выбор Connection Profile и API Preset.
├─ style.css                     — кнопки, popup и состояния выполнения.
├─ README.md                     — установка, использование и ограничения.
├─ package.json                  — только локальные проверки через Node.
└─ tests/
   ├─ prompt.test.js             — состав и порядок prompt.
   ├─ generation.test.js         — таймаут, ошибки и восстановление конфигурации.
   └─ undo.test.js               — снимки, swipes, stale-state и смена чата.
```

## Критерий завершения

Работу можно считать законченной, когда одновременно верны все пункты:

1. SillyTavern устанавливает и загружает feedPros без ошибок; у каждого отображённого сообщения есть по одной кнопке Feedback и Undo.
2. Popup всегда открывается пустым, имеет четырёхстрочное поле шириной не более 600 px; `Enter` отправляет, `Shift+Enter` переносит строку, пустой ввод ничего не меняет.
3. Запрос содержит весь актуальный чат без выбранного сообщения на исходной позиции, а текущая версия цели находится последней; успешный ответ заменяет только её текст и активный swipe.
4. Ошибка, пустой ответ, смена чата, изменение цели во время ожидания, таймаут 30 секунд и поздний ответ не изменяют сообщение.
5. Один общий Undo восстанавливает последнюю успешно заменённую версию, сохраняется после reload того же чата и очищается при переходе в другой чат.
6. Временно выбранные Connection Profile и API Preset применяются к Feedback-запросу и восстанавливаются при любом исходе.
7. Автоматические тесты проходят, а ручной smoke-тест подтверждает рабочий поток Feedback → повторный Feedback → Undo в SillyTavern.

### 6. Сделать замену сообщения и единый Undo транзакционными — НЕ НАЧАТО

Между открытием popup и ответом модели пользователь может изменить или удалить сообщение. Такие результаты нельзя применять по старому индексу вслепую.

- [ ] Перед применением результата повторно проверь chat key, индекс, тип/имя и точное совпадение текущего `mes` с текстом, отправленным модели. Несовпадение → stale-state без изменения.

Проверка этапа: тесты доказывают цепочку `A → Feedback B → Feedback C → Undo B`; отдельный тест подтверждает, что неудачная попытка после C не уничтожает возможность вернуть B.

## Проверка и критерии готовности

- `npm run check` подтверждает синтаксис и подключённость всех JS-модулей.
- `npm test` подтверждает prompt, timeout, restore, stale-state, swipes и lifecycle buffer без реальной сети.
- Успешная загрузка manifest и отсутствие ошибок консоли подтверждают корректную интеграцию extension.
- Ручной smoke-тест подтверждает DOM, Popup, сохранение chat, реальные profile/preset и повторный рабочий цикл.
- Реальная модель нужна только для финального smoke; автоматические тесты не должны расходовать API-токены или требовать секреты.
